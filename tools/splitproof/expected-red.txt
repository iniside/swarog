# Splitproof checks known to be red, one `id | signature | reason` per line: id is the check's
# leading [..] text, signature is text the failure detail must contain, reason says why it is red.
# A signature may hold several fragments joined by `&&` (spaces around each are trimmed); the
# detail must contain every fragment, in any order. Use one fragment per independent field the
# check reports, so a field that changes on its own is caught:
#   PH6 | grant=404 && subscription=Some(("active", 0)) | ...
# A signature cannot contain `|` and a fragment cannot contain `&&`.
# A failed check listed here whose detail carries the signature is expected; one whose detail
# lacks a fragment is changed (red for another reason); one not listed is new; a listed id whose
# check passed is stale. Changed, new or stale fails the run, so remove an entry in the commit that
# turns its check green and re-derive a signature when its check fails differently. Every id names
# one check: two checks with one id fail the run, even when one of them passes.
