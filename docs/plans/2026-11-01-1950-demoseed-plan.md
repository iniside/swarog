# Plan: `tools/demoseed` — deterministic demo data through the public API

## Context

**Owner's request (his words):** "powinno dać się zaseedować jakieś fake dane do postgresa, żeby ten panel coś pokazywał" — "to będzie mały tool". Purpose: the admin panel shows real-looking data for screenshots before/after the upcoming admin refactor.

**Owner-accepted defaults (proposed in chat, not objected to):** a separate tool run on an already-running fleet (not a `devctl up` flag); screenshot scale (~30 players, ~100 matches); deterministic data (same content every run).

**Explicit exclusions:**
- No direct SQL into module schemas. Every row is created through the gateway's public HTTP API, so the owning module's code writes it, durable events fire, and audit / leaderboard / rating / notifications fill as a side effect. A direct INSERT would bypass fortress ownership (archcheck forbids foreign-schema SQL for modules; a tool doing it would still be a "contract on paper").
- No admin-portal form driving (wallet grant, config upsert, mail test send) — a separate plan (see Decided).
- No party seeding: party is ephemeral (heartbeat-driven) and has no admin view.
- No new module, event, contract, or `devctl` change. The tool does not take `run/rollout.lock` (it is a client of a running fleet, not a rollout).

### Overlap map (why not extend X)

| Candidate | What it does | Why not extend / depend on it |
|---|---|---|
| `tools/splitproof` | Proof harness; drives the same HTTP flows with private helpers in `main.rs` | It is proof surface with assertions and a fleet lifecycle; its helpers are private to the bin (`src/lib.rs` exports only `Running`, `fleet_liveness`). Seeding is not proof. demoseed copies its patterns (X-Api-Key + Bearer headers, json!/Value, 429 retry at `tools/splitproof/src/main.rs:1140-1167`), never imports it. |
| `tools/adminctl` | DB-direct admin user mint | Admin portal users only; DB-direct is exactly what this tool must not do for domain data. |
| Module dev seeds (`APIKEYS_DEV_SEED`, `WALLET_DEV_SEED`) | Env-flag upserts in `migrate` | Catalog/keys only; adding demo players there would put demo data into module code and boot. |
| `devctl up` | Fleet supervisor; sets the dev flags demoseed relies on | Owner default: separate tool; devctl stays a supervisor. |

### Verified facts (anchors)

- Gateway monolith base `http://127.0.0.1:8080`, split front door `:8082` (`tools/processctl/src/fleet.rs:984,1030`, `:824,852`).
- `devctl up` (Development flavor) sets `APIKEYS_DEV_SEED`, `ACCOUNTS_DEV_AUTH`, `INVENTORY_DEV_GRANT`, `WALLET_DEV_SEED` = 1 (`fleet.rs:992-995` monolith, `:908-911` split).
- Every op needs `X-Api-Key`; player ops also `Authorization: Bearer <token>` (`modules/gateway/src/lib.rs:17-31`). `dev-key-client` = player allow-list; `dev-key-server` = full, required for `match.report` (`modules/apikeys/src/lib.rs:100-132`).
- Gateway HTTP limiter `RATE_LIMIT_RPS`/`RATE_LIMIT_BURST` (`core/app/src/lib.rs:1063-1069`), always-on at the gateway → 429.
- Ops (catalog `opscatalog/src/generated.rs`):
  - `POST /accounts/register` `{"email","password","displayName"}` → 201 `Session{player_id,token,..}`; duplicate email → Conflict (`modules/accounts/src/tests.rs:767`). `POST /accounts/login` `{"email","password"}` → `token`. `GET /accounts/me` → `handle`.
  - `POST /characters` `{"name","class"}` → 201; per-player cap → 409.
  - `POST /inventory/me/grant` `{"item_id","qty"}`; catalog ids `coin`, `starter_sword`, `health_potion` (`modules/inventory/src/lib.rs:68-72`).
  - `POST /match/report` `{"ReportId","Winner","Loser"}` with `dev-key-server`, no bearer → 202; same ReportId + same result = no-op, different = 409; Winner ≠ Loser, non-empty (`modules/match/src/lib.rs:59-63,198-215`).
  - `POST /friends/requests` `{"target_handle"}` → 201 `Friend{edge_id,state,..}`; a repeated request is **201 with the current state**, never 409 (`api/friends/api/src/lib.rs:121-126`); target `POST /friends/requests/{edge_id}/accept` → 204, but **404 on an already-accepted edge** (`:141-145`).
  - `POST /groups` `{"name","join_policy"}` (`open`/`request`/`invite`, `api/groups/api/src/lib.rs:57-64`); **duplicate names are accepted** (no UNIQUE, `modules/groups/src/lib.rs:61,65`). `POST /groups/{id}/join` `{}` (409 if a row exists, `:159`); `/invites` `{"target_handle"}` (409 if a row exists, `:174-176`); `/respond` `{"decision"}` (**404 unless the row is `invited`**, `:182-186`); `/decide` `{"subject_id","decision"}` (409 on an existing member, `:195`).
  - `POST /characters`: no name uniqueness; the only 409 is the cap `MAX_PER_PLAYER = 10` (`modules/characters/src/service.rs:17,165-170`).
  - `POST /inventory/me/grant` ADDS `qty` to holdings (`api/inventory/api/src/lib.rs:68-80`, `modules/inventory/src/lib.rs:55-59`).
  - `match.report` `Winner`/`Loser` are free strings; leaderboard/rating store them as given (no admin page for either; only audit shows matches).
  - `POST /storage/{collection}/{key}` `{"value": "<json text>", "expected_version": 0, "acl": "private"|"public_read"}`.
- Admin views filled by this (research report): Players, Characters, Inventory, Friends, Groups, Cloud Saves, Audit (durable topics incl. `player.registered`, `character.created`, `match.finished`, `friend.*`, `group.*`), Inbox (notifications from event consumers — `modules/notifications/src/lib.rs:161-197`). Stay empty: Wallet ledger, Mail, Config (Q1).
- Tool crate conventions: explicit `members` entry in root `Cargo.toml:32-95`; `version/edition/license.workspace = true`, `publish = false`, explicit `[[bin]]`; hand-rolled argv (no clap, `tools/adminctl/src/main.rs:3-4`); `reqwest = { workspace = true }` (rustls, ring-only — `cargo tree -i aws-lc-rs` must stay empty, `Cargo.toml:269-278`); clippy `--workspace --all-targets -D warnings` applies. No archcheck/verifyctl list edits needed.
- `cargo run -p devctl -- up` keeps its parent Cargo alive; no other Cargo command may start while it runs (`.agents/shared/gamebackend.md` Commands). So demoseed is BUILT before the fleet starts and RUN as `target/debug/demoseed(.exe)`.

### Decided

Wallet balances, config entries and mail have no public JSON create route; those views stay empty. Owner (2026-11-01): admin-portal work is "kompletnie osobny plan" — no admin-form driving in this tool.

## Steps

### Step 1 — Create the `demoseed` crate and seeder `[opus]`

(a) New `tools/demoseed/Cargo.toml`, `tools/demoseed/src/lib.rs`, `tools/demoseed/src/main.rs`; root `Cargo.toml` `members` gains `"tools/demoseed"` beside the other tools. Purely additive: no existing seeding mechanism (module dev seeds, adminctl, splitproof fixtures) changes or dies.

(b) First: everything else (tests, docs) builds on this crate.

(c) How:
- Deps: `reqwest`, `tokio` (`rt-multi-thread`, `macros`, `time`), `serde_json`, `anyhow` — all `workspace = true`. No `api/*`, `modules/*`, `gateway`, `splitproof`, `processctl` deps; bodies are `serde_json::json!`, responses `serde_json::Value` (splitproof precedent).
- CLI (hand-rolled): `demoseed [--base-url <url>] [--players <n>] [--matches <n>]`; defaults `http://127.0.0.1:8080`, 30, 100. Password is a fixed dev constant in code (never argv).
- `lib.rs` splits a PURE plan from HTTP execution:
  - `pub fn plan(players: usize, matches: usize) -> SeedPlan` — deterministic, no I/O, no clock, no `rand` crate: a small fixed-seed splitmix64 in-crate. Produces: players (`demo-NN@demo.local`, display names from a fixed list), 1-3 characters each (name + class from fixed lists, names unique per player), item grants as TARGET quantities (item id + qty), matches (`ReportId` `demo-match-NNNN`, winner ≠ loser, referenced by player index in the plan), friend pairs (no self, no duplicate unordered pair), 4 groups (one per policy plus one extra open, unique names) with members, one storage save per player (collection `saves`, key `slot1`, small JSON value).
  - `pub enum Outcome { Created, AlreadyExists }` and `pub fn classify(status: u16) -> Result<Outcome, Retry/Fail>`: 2xx → Created, 409 → AlreadyExists, 429 → retry, other → error. One function decides HTTP status meaning; it gets NO per-op 404 exceptions — re-run safety comes from the read-before-write gates below, not from widening `classify`.
  - Executor (async), convergent — every step reads current state first and writes only what is missing:
    - players: register (409 → AlreadyExists), then login → `token` + `player_id`, `GET /accounts/me` → `handle`. On the wire, matches use `Winner`/`Loser` = that `player_id` (from the `Session`, `api/accounts/api/src/lib.rs:45-47`).
    - characters: `GET /characters`, create only planned names not present (the 409 stays a pure cap guard).
    - inventory: `GET /inventory/me`, grant only the shortfall up to the planned target quantity.
    - matches: `POST /match/report` with `dev-key-server`; a re-sent identical report is a 202 no-op.
    - friends: request → read `Friend.state` from the 201 response; call accept (as the target) only when `state == "pending"`.
    - groups: the creator's `POST /groups/list`, create only planned names not present (duplicates are accepted by the server, so this lookup is required). Membership per policy: `open` → join (409 = already a member); `request` → join, then the owner decides ONLY when that join returned Created; `invite` → owner invites, then the invitee responds ONLY when that invite returned Created.
    - storage: put with `expected_version: 0` (409 = already saved).
  - 429: bounded retry with backoff, as splitproof (`tools/splitproof/src/main.rs:1140-1167`); no extra pacing (~600 calls at the default 20 rps / 40 burst, `core/app/src/lib.rs:1050-1069`, is ~30 s).
  - Re-run idempotency: a second run on the same DB creates nothing new and exits 0; an interrupted run is completed by the next one.
  - Ends with a one-screen summary: counts created vs already-existing per kind, and the admin URL for both topologies — monolith `<base>/admin`, split `http://127.0.0.1:8085/admin` (`tools/processctl/src/fleet.rs:847`). No topology probe.
- Fail fast with a clear message if the base URL is unreachable or `ACCOUNTS_DEV_AUTH` is off (register → 404).
- comments: default NONE; at most: why `match.report` uses the server key; why the plan is pure.

Verify: first a cargo/rustc liveness check as its own call (stop if anything runs), then `cargo build -p demoseed`, `cargo clippy -p demoseed --all-targets -- -D warnings`, `cargo tree -i aws-lc-rs` (expect empty); report the observed output and exit codes. No fleet, no `cargo test` of other crates, no `cargo fmt`. Commit `feat(demoseed): seed deterministic demo data through the gateway API (demoseed step 1)`.
